快速上手 Multikernel

安装 multikernel 内核和 kerf 工具，划出 CPU 和内存，并在主内核旁启动你的第一个内核实例。

在 GitHub 上查看 了解架构

概述

Multikernel Linux 在同一台机器上并行运行多个相互独立的 Linux 内核。每个内核拥有自己的 CPU、内存和分配给它的设备，直接运行在硬件之上，无需虚拟机管理程序。本指南将带你从一台普通的 Linux 主机开始，最终运行起一个直接启动进容器镜像的内核实例。

本指南使用以下术语：

  • 主内核：机器启动时运行的、支持 multikernel 的内核。它与常规 Linux 内核的行为一致，并且还能生成其他内核。
  • 资源池：主内核为其他内核预留的 CPU、内存和设备。
  • 实例：从资源池中划出的一份具名资源，以及加载到其中的内核。
  • 子内核：在实例中运行的内核，拥有自己的调度器、网络协议栈和设备视图。

开始之前

x86_64 提供预构建的软件包。其他架构需要从源码构建内核和 kerf。

架构 内核 Kerf
x86_64 deb 或 rpm 软件包，或源码 deb 或 rpm 软件包、PyPI，或源码
arm64 源码 PyPI 或源码
RISC-V 源码，另需设备树文件 PyPI 或源码

你还需要：

  • root 权限。会改变内核状态的 kerf 命令需要通过 sudo 运行。
  • 主机可以让出的 CPU 和内存。放入资源池的资源在释放之前不再归主机使用。
  • 正在运行的 Docker 守护进程，如果你像本指南一样从容器镜像启动实例。
  • 从源码构建时：常规的 Linux 内核构建工具链、Python 3.8 或更高版本及 pip，以及 kerf 所需的 musl-gcc。

1 安装 Multikernel 内核

主机必须运行开启了 CONFIG_MULTIKERNEL 和 CONFIG_MKTTY 的内核。你可以通过软件包安装，也可以从源码构建。

方式 A：deb 或 rpm 软件包（x86_64）

从发布页面下载适用于你的发行版的内核软件包，安装后重启进入新内核。软件包中的内核已开启上述两个选项。

# Debian / Ubuntu
sudo apt install ./linux-image-<version>_amd64.deb

# Fedora / RHEL
sudo dnf install ./kernel-<version>.x86_64.rpm

sudo reboot

如果要在第 3 步构建 DAXFS 等树外模块，请同时安装同一版本的 linux-headers（deb）或 kernel-devel（rpm）。

方式 B：从源码构建

git clone https://github.com/multikernel/linux.git
cd linux
cp /boot/config-$(uname -r) .config  # 以当前运行内核的配置为起点
make menuconfig                      # 开启 CONFIG_MULTIKERNEL=y 和 CONFIG_MKTTY=y
make -j$(nproc)
sudo make modules_install
sudo make install
sudo reboot

CONFIG_MULTIKERNEL 依赖 CONFIG_MEMORY_HOTPLUG、CONFIG_MEMORY_HOTREMOVE 和 CONFIG_CONTIG_ALLOC。如果起始配置中没有开启，请先开启它们。内核借助这些功能在运行时为子内核划出内存，因此无需额外的模块或启动参数。

另外请开启 CONFIG_MULTIKERNEL_VSOCKETS，即内核之间的 vsock 传输。kmorph 依赖它，第 6 步中的 kerf exec 也通过同一传输运行。

RISC-V 上的额外步骤

RISC-V 开发板通过设备树启动，因此还需要构建并安装设备树文件。请在 make -j$(nproc) 之后、重启之前运行以下命令：

make dtbs
sudo make dtbs_install INSTALL_DTBS_PATH=/boot/dtbs/$(make -s kernelrelease)

请将 INSTALL_DTBS_PATH 设置为引导加载程序读取设备树的目录。

验证

重启后，确认当前运行的内核支持 multikernel：

uname -r
grep -E 'CONFIG_(MULTIKERNEL|MKTTY)=' /boot/config-$(uname -r)

两个选项都应显示为 =y。

2 安装 Kerf

Kerf 是管理资源池和实例完整生命周期的命令行工具：创建实例、向实例加载内核、启动实例以及销毁实例。

方式 A：deb 或 rpm 软件包（x86_64）

从 kerf 发布页面下载软件包并安装：

# Debian / Ubuntu
sudo apt install ./kerf_<version>_amd64.deb

# Fedora / RHEL
sudo dnf install ./kerf-<version>.x86_64.rpm

方式 B：PyPI

发行包名为 kerf-multikernel，安装后的命令是 kerf。

pip install kerf-multikernel

方式 C：从源码安装

适合需要跟踪开发版本的场景。构建过程会编译静态链接的 kerf-init，需要 musl-gcc（Debian 和 Ubuntu 上为 musl-tools 软件包）。

git clone https://github.com/multikernel/kerf.git
cd kerf
sudo pip install .

验证

kerf --help

注意：后续步骤通过 sudo 运行 kerf，因此该命令必须位于 root 的 PATH 中。以普通用户身份执行 pip install 会将其安装到 ~/.local/bin，而 sudo 默认不会搜索该目录。

3 加载 DAXFS 模块

DAXFS 是一个通过直接内存访问在多个内核之间共享的文件系统。Kerf 用它把容器镜像交给子内核作为根文件系统。DAXFS 是树外内核模块，kerf 不会自动加载它。

git clone https://github.com/multikernel/daxfs.git
cd daxfs
make
sudo insmod daxfs.ko

子内核同样需要 DAXFS 支持：将其编译进子内核，或在第 5 步通过 --initrd 传入会加载 daxfs.ko 的 initramfs。

注意：只有从容器镜像启动或共享主机目录时才需要 DAXFS。仅通过 --initrd 以传统方式从 initramfs 启动的实例不需要它，可以跳过这一步。

4 初始化资源池

资源池存放可分配给实例的 CPU 和内存。内核直接从运行中的主机划出资源池，因此无需重启。

# 将 CPU 4-31 和 8 GB 内存放入资源池
sudo kerf init --cpus=4-31 --memory=8GB

请根据你的机器调整这些数值，并注意：

  • CPU ID 是物理 ID，而不是大多数工具显示的逻辑 CPU 编号：在 x86 上是 APIC ID，在 arm64 上是 MPIDR。在 x86 上可以用 grep -E '^(processor|apicid)' /proc/cpuinfo 查看。
  • 内存只写大小时，会从所请求 CPU 所在的 NUMA 节点分配。如需明确指定节点，请写成 --memory=8GB@0,8GB@1。
  • 设备也可以放入资源池，通过设备名或 PCI 地址指定，例如 --devices=nvme0n1,enp9s0。

加上 --dry-run 可以预览结果而不做任何更改。用不同的数值再次运行 kerf init 可以调整已生效的资源池。

5 创建并启动实例

启动一个实例需要三条命令：从资源池分配资源、加载内核、启动。

# 从资源池分配 4 个 CPU 和 2 GB 内存
sudo kerf create web-server --cpus=4-7 --memory=2GB

# 加载内核，使其直接启动进 Docker 镜像
sudo kerf load web-server --kernel=/boot/vmlinuz-$(uname -r) --image=nginx:latest

# 启动实例并连接到它的控制台
sudo kerf start web-server --console

使用 --image 时，kerf 会从 Docker 镜像构建 DAXFS 镜像，子内核直接将其挂载为根文件系统。示例中加载的是主机正在运行的同一个 multikernel 内核；任何开启了 CONFIG_MULTIKERNEL 的内核都可以使用。

子内核在分配到的 CPU 和内存上启动，直接运行在硬件之上。它的控制台默认为 mktty0，--console 连接的就是这个控制台。要在不停止实例的情况下断开控制台，请先按 Ctrl+]，再按 .。

如需以传统方式启动，请将 --image 换成 --initrd，并通过 --cmdline 传入内核参数。运行 kerf load --help 可以查看全部选项，包括实例的网络设置。

6 管理实例

实例运行之后，你可以在主机上查看它、在其中执行命令，以及调整它的资源。

# 列出所有实例，或查看某个实例的详情
sudo kerf show
sudo kerf show web-server

# 在实例中执行命令，用法与 docker exec 相同
sudo kerf exec web-server ls /
sudo kerf exec -it web-server sh

# 调整运行中实例的资源
sudo kerf update web-server --memory=4GB

内存以内核的内存粒度为单位调整，kerf 会拒绝不是该粒度整数倍的大小。加上 --dry-run 可以只验证更改而不实际应用。

命令 用途
kerf init 创建、调整或释放资源池
kerf create 从资源池分配一个实例
kerf load 向实例加载内核，以及可选的 initrd 或容器镜像
kerf start 启动实例
kerf exec 在运行中的实例内执行命令
kerf show 显示实例及其资源
kerf update 更改实例的 CPU、内存或设备
kerf dump 将资源池或实例保存为设备树，可通过 kerf init --input 和 kerf create --input 重放
kerf kill 关闭运行中的实例
kerf unload 卸载实例中的内核镜像
kerf delete 删除实例，并将其资源归还资源池

每条命令的选项都可以通过 kerf <command> --help 查看。

清理

关闭并删除实例，然后将资源池中的 CPU 和内存归还主机：

sudo kerf kill web-server
sudo kerf unload web-server
sudo kerf delete web-server

# 将资源池中的全部资源归还主机
sudo kerf init --cpus=none --memory=none

如果实例无法正常关闭，可以使用 kerf kill --force 强制停止。
